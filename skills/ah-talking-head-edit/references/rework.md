# 返工与历史规则复核

用户反馈吞字、重复、间隔或字幕问题时读取本页。学习的是用户确认的判断方式，不是照搬历史工程或把历史参数固定到所有视频。

## 重新建立当前版本

- 先核对原片哈希、当前工程身份、当前源区间、速度和实际导出版本。旧计划和旧验收报告只能解释历史，不证明当前工程正确。
- 对比人工版与自动版时统一源素材和速度，区分源时间与输出时间。操作录屏中的教学声音和等待不作为成片口播。
- 逐项登记反馈的输出时间、对应源区间、修改前后边界、理由和核听状态。人工精修也要独立检查空白、吞字和字幕残字。
- 用户在原生界面修改工程后，暂停代理写入和保存，重新读回；不得覆盖用户新状态或沿用旧版验收。

## 恢复尾字不能带回废弃表达

- 不统一向所有切口加固定缓冲。逐个核对原片上下文、废弃半句和选定完整表达，在该表达范围内恢复尾音。
- 扩展边界后检查是否进入已删的重说，重算映射和保护发音，重跑音频清单复用检查。两个区间不重叠也可能各含一次同词，仍须比较原声。
- 恢复一个字后核听整个衔接句，不以“尾字出现了”单独判通过；同时检查前词尾、后词起音和重复呼吸/词语。
- 既有尾字恢复记录曾使相邻源区间重叠，证明机械扩展有重复风险；这不能证明另一处重复一定由同一原因造成。

## 停顿检查必须实际运行

独立输出完成后运行本项目自己的工具：

```bash
python3 scripts/pause_audit.py --video 无字幕母版.mp4 --project 自有工程.json --render-report validation-report.json --report 新停顿报告.json
```

工具在输出母版上检查低能量，默认 -32 dB、0.25 秒仅供候选发现。噪声环境不同时记录并调整阈值；不据此自动删片。项目和母版必须与完成的 render 报告哈希一致；使用重新计算的映射标记候选跨过的接点，不信任旧 creation_mapping 缓存。

逐个处理 CHECK，优先检查 0.4 秒以上，0.8 秒以上写明确理由。候选内的轻声、英文音节、强调停顿、演示等待都可能应保留。跨切口空白在最终母版上合并检查，不能两边分别短于阈值就忽略。

## 验收失效范围

| 修改 | 需要重做的检查 |
| --- | --- |
| 原片、剪口、速度、有声轨道变更 | 音轨、语义、切口、停顿、导出；重新让剪映识别字幕 |
| 只改字幕错字 | 核对原文和改后字、重导最终 SRT、字幕画面检查 |
| 只补字幕显示空隙 | 显示覆盖检查；不据此宣称语音同步通过 |
| 原生保存改变轨道或速度 | 重新读回、播放和导出；保留机器验证失败结果 |

机器验证、显示覆盖、文字准确、语音同步、原生持久化、人工听音分别报告。不能为得到通过删除保护发音、改松验证器或把待核听状态改成已通过。

## 外部模型审查

遇到具体流程疑点且用户授权外部模型时，可把已核实案例和问题发给指定模型；先核对页面账号和模型。模型回复仅是建议：对照原始记录和实际脚本验证后再采用。未经听音或没有工程读回依据的诊断不升级为事实；模型拒答或页面不可用时如实记录，继续能完成的本地核查。
