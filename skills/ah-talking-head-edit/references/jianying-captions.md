# 剪映原生字幕与完整交付

用户选择本流程时，`ah-talking-head-edit` 仍是执行入口。独立脚本负责保留区间、倍速、无字幕视频和 JSON 工程；剪映通过官方界面负责最终字幕识别和原生导出。不要因需要剪映字幕切换到另一个剪辑 Skill。此流程不调用旧剪辑引擎，不分发剪映库，也不把自有 JSON 冒充剪映草稿。

## 清空和识别

1. 保留原片、旧成片和工程。在剪映中复制现有任务，或新建工程导入独立脚本导出的无字幕视频。先确认画面没有烧录旧字幕；已经烧进像素的字不能靠清空文字轨去除，须回到无字幕源片重导。
2. 最终剪口和速度固定后再生成字幕。用户要求剪映识别时，禁止调用本地模型重新生成最终字幕。
3. 清空副本所有旧口播字幕轨，再运行剪映“识别字幕”。勾选“同时清空已有字幕”只是动作，不是验收：历史脚本生成的文字轨可能仍保留。检查实际轨道和预览，确认仅有一套有效口播字幕，没有上下两层重复。
4. 导出剪映识别的 SRT，保留原始识别文件。按画面、原声和上下文逐条校对中文、数字、英文产品名和本人姓名；不改说话含义，不把口语润色成书面语。

## 只改字并补显示空隙

- 保留剪映分成的每一条及其顺序，不合并、拆分、重排字幕，不按语义重新切割。文字修正必须按 cue 明确记录原文和改后文字。
- 用户要求全程铺满时：首条显示从 0 开始；每条结束补到下一条原识别开始；末条补到主视频终点。除首条起点和各条终点外，原识别起点保持不变。
- 不为补空隙凭空补字，不改变音视频剪口。明确无字幕片头或长演示例外按请求处理；不得强行宣称全程铺满。
- 使用 `scripts/captions.py prepare` 输出校正后 SRT 和变更报告，再用 `audit` 检查首尾、全部空隙、重叠、空文字和越界。机器通过不等于文字与声音准确。
- 导入校正 SRT 前清空上一轮字幕。导入后检查分段数量和顺序；不能把两套字幕叠在一起交付。
- 已明确的阿杭系列样式为字号 11、胸口位置、白字黑边；当前要求优先。检查首帧、中间、修改处和尾帧是否可见、遮脸或裁切。

## 保存、重开和导出

- 使用官方界面打开、播放、保存，正常退出再冷重开检查，保留实际项目身份。不得强杀正在编辑的剪映。
- 导出当前版本到用户指定主题目录，新文件序号接续现有序号；保留旧成果。导出完成后核对真实容器、尺寸、帧率、时长和音视频完整解码。
- 重新从最终工程导出 SRT 用 `audit` 检查，不能只验证导入前的计划；首尾和原空隙处还须检查真实成片。
- 交付 MP4、校对后的 SRT、自有 JSON 工程、实际原生草稿路径和校验报告。报告逐项区分机器、原生播放、保存、冷重开和人工听音；未完成项如实保留。
- 原生界面不可用时继续独立部分，交付状态标为缺少原生字幕或原生验收，不换用本地模型、不用旧视频冒充这次成片。
